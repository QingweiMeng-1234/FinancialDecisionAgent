# 金融新闻事件标注规范 v1

用途：新闻正文 → 投研关注事件。用于校准现有七字段 schema，不用于生成交易指令。第一轮草稿见 [12 篇新闻全文与标注](../datasets/event_structuring/2026-09-08/annotation-round1/review-pack.md)，完整候选及复核流程见 [数据说明](../datasets/event_structuring/2026-09-08/README.md)。

## 收录边界与事件粒度

优先收录本文报道的具体变化：经营结果、已宣布的指引调整、融资或重大资本行动、政策决定、产能项目、明确的证券价格变化。纯人物生活、个人购物体验、没有新增事实的评论可返回空列表。日程提醒不等于财报已发布，市场预期不等于政策已实施。

公告本身是已发生的事件，即便公告内容是未来计划。解释必须保留“宣布、计划、可能、内部测试”等限定，不能写成已投产、已出售、已上市。现有 schema 没有事实状态字段，暂用 reasoning 保存限定，不新增未被下游支持的字段。

以“主体＋同一次业务变化”为一个事件。多主体受到不同影响时分开；同一股价变化的盘前和开盘后更新通常合并，避免重复。历史背景不重复抽取；如果旧事件是本文的唯一事实依据，交由复核者决定是否收录，不能自动标为完整金标准。

## 字段定义

| 字段 | 规则 |
|---|---|
| event_type | Company：单一公司/项目主体的经营或资本事项；Macro：宏观数据和公共政策；Sector：行业整体变化；Market：实际证券或资产价格/交易市场变化。一个地区不能因有资金活动就标为 Company。 |
| affected_asset | 优先正文明确给出的证券标识，否则用正文明确的主体名称。不能凭模型记忆猜 ticker。宏观目标用清晰的资产/政策对象；没有更具体对象时用 General Market。普通股与优先股要区分。 |
| direction | 相对于 affected_asset 的文中明确变化。报告的股价涨跌可以直接对应方向；营收指引上调/下调对应正面/负面。融资承诺、行政变更、尚不能确认收益的计划宜 Neutral；不能自动推断对股价的影响。 |
| importance | High：对主体经营、资本结构或宏观政策有显著影响的核心事件；Medium：明确但影响范围较有限的业务变化；Low：局部或执行层面的变化。没有金额/范围依据时不能仅因标题热度标 High。争议项保留待裁决，不强行凑标签。 |
| time_horizon | Short-term：主要在未来12个月以内体现或是当期市场变化；Long-term：明确跨年度或结构性影响；Both：正文同时支持两类影响。不是发布时间的远近，也不是模型对持有股票期限的建议。 |
| reasoning | 1—2句原文支持的说明，保留主体、时态和归属。不引入新闻以外的因果链、收益预测或买卖建议。 |
| evidence_excerpt | 正文中的连续逐字片段，可包含相邻句子。保留原有金额、单位、百分号和限定。不要改写、补省略号或拼接不相邻句子；标题和模型解释不能替代正文证据。 |

重要性、方向和期限是按产品用途制定的标签，并非客观金融真理。先由复核者校准这套规范，再将稳定规则写入训练数据；不要用模型自己的标签来证明模型准确。

## 重点反例

- “可能出售最多12.5亿美元Bitcoin”：计划事件，不是已经出售。
- “下载量30亿”：使用/分发指标，不是30亿用户或收入。
- “内部员工测试新模型”：不是已公开发布，也不能推导盈利提升。
- “预测未来万亿估值”：是有归属的预测，不是当前市值。
- “承诺未来融资”：不等于已完成的自有资金投资。
- “利率可能上升”：没有政策决定时不能标成已加息。
- “没有披露”：不等于零、下降、不存在。

## 复核流程

1. 阅读完整正文，核对其内容 hash 与候选文件的 source_content_sha256。
2. 判断是否需要事件，以及是否漏掉另一主体或另一事件。
3. 按表核对全部字段；有引用不代表引用支持 reasoning。
4. 明确无事件时使用 `expected_events: []`；未知/未复核不等于无事件。
5. 将确认后的 proposed_events 放入 expected_events，设置 reviewed=true，并记录 review_metadata（复核者、时间、规范版本、修改说明）。不能仅将助手草稿整批改为已复核。
6. 在完整200篇候选中按 case_id 合并修改；不要改变已有 split 来追求好看的分数。检查同一新闻事件的不同报道是否跨 split，必要时按故事组一起调整并生成新数据版本。

助手草稿始终标为 `annotation_status: assistant_draft`、`reviewed: false`，不伪装成人工复核结果。首批选择的是 train 中较短的文章，不代表完整金融新闻分布。test 预留24篇，其中6篇已在基线调试中看过，最终盲测需要单独隔离这6篇或补充未用于调参的数据；不能在看到测试结果后重新分组来提升成绩。

## 数据质量问题

现有语料含有乱码及可疑单位。标签以提供的正文为依据，但发现异常时必须标记 review_notes，不能擅自修正数字。影响主体/证据理解的严重乱码样本应先隔离或修复原文，再重新计算 hash 和标注。原文支持抽取仅表示“这篇文章这样报道”，不代表报道已被外部事实核验。
